# 3MB・0.1秒の目標と速度検証

2026-10-29の最新指定により、目標を **モデル配布3,000,000 bytes以内・ふつうのお題1件0.1秒以内** に変更した。途中で指定された8MBや、旧32MB候補を現在の採用上限としては使わない。自然な日本語、童話調の軽減、固定文型を推論に使わないこと、新規文の多様性という目的は維持する。

## 現在のデモ

標準のv2と、以前作成した日常文の小型v3を切り替えられる。日常文v3は重み・語彙・設定・manifest・LICENSEを合わせて **2,423,935 bytes**。新しい蒸留モデルの完成ではなく、小型・高速な比較基準としての配置である。アプリ向けの標準モデルは変更していない。

v3の以前の点検は自然さ・読みが確認用98/100、童話調0/100だった。一方、新規正規化本文は約33〜34%で、多様性の目標には不足する。速度条件を満たしたことを、新規文生成の目標達成と同一視しない。詳細は [日常文の実験](everyday-generation.md)。

## 推論の改善

- 必要なのは次の1トークンの確率だけなので、過去の全位置について出力語彙への射影とホスト配列への変換を行う処理をやめ、最後の位置だけを射影する。Transformer本体の過去prefixの再計算はまだ残る。KV cacheを実装済みとはしない。
- subword候補を1件ずつ検査する代わりに、同じ文字prefixの候補をまとめて辞書と照合する。合法な候補の集合と、かな長・語境界・読みの規則は変えない。候補を選んだ後にその経路だけを確定する。
- 旧方式の個別照合と新方式の候補マスクが、prefix共有・先頭空白・語の途中・終端・長さ上限で一致する回帰試験を追加。最後の位置だけの確率も、従来の全位置計算と数値照合する。

これらは全文一覧や新たな文型による高速化ではない。推論時の無駄な計算と照合の削減であり、学習済みの重みは変更しない。

## 実測

手元のWindows x86_64環境、releaseビルド、Intel Family 6 Model 183。CPU測定は履歴0、各20件の探索的な測定。ブラウザーはEdge 156.0.4314.50の実Web Worker、各30件、難易度normal。ブラウザーではモデルが指定する履歴を保持し、小型v3はtemperature 1.0、top-p 0.95、履歴128件。標準v2はtemperature 0.8、top-p 0.95、履歴16件。

| 測定 | 中央値 | p95 |
|---|---:|---:|
| 標準v2・CPU（改善後） | 33.8ms | 64.0ms |
| 小型v3・CPU（改善後） | 28.9ms | 47.9ms |
| 標準v2・ブラウザー | 20.6ms | 32.8ms |
| 小型v3・ブラウザー | 15.2ms | 33.5ms |

今回のブラウザー測定では100ms以内に収まった。ロード・ダウンロード・画面描画の時間は含まない。CPUとブラウザーは設定・履歴・実装系が異なるため、その数値で優劣を断定しない。サンプル数も少なく、他の端末や連続使用で常に100ms以内を保証する測定ではない。

旧大型v8にも同じ推論改善を適用した探索測定では、CPU中央値375ms→243ms、p95 1,975ms→1,141ms。改善しても今回の目標には不適合であり、現在のデモビルドには含めない。元データと設定は [速度測定JSON](lightweight-speed-measurements.json) に保存した。

## 大型の日本語本体を圧縮した研究資産

方針変更前に、LLM-jp-3-150mの12層を維持し、語彙を6,000項目に再分割した候補v10を実装した。RMSNorm・RoPE・SwiGLU、独立した出力埋め込み、block-128 INT4保存をPython/Rust/WASMで扱える。約56.49Mパラメータ、配布31,368,510 bytesなので、新しい3MB上限には合わない。

単純な学習後4bit化では共通検証文のtoken NLLが2.197→3.846と悪化した。丸め誤差を学習中にも再現する基本的なstraight-through QATを加えると、4bitで2.177まで回復した。この数値は自然さを保証しない。元モデルの保持語彙に対するlogit移植の照合と実ブラウザーの3難易度生成は通ったが、600seedの大型候補評価はユーザーの方針変更で中断した。出力品質の合格や、ParetoQ等の論文全体を再現した成果とはしない。

QAT後は一部の大きいlogitが約164となり、PyTorch/Candle間の最大絶対差は約0.00058。絶対許容差0.0002だけの照合では不合格だった。明示的な相対許容差0.00001を追加した照合では60,000値すべてが `abs_error <= 0.0002 + 0.00001 * abs(reference)` を満たした。CLIの既存の既定値は相対許容差0のまま。数値照合の条件を文章品質の基準と混同しない。

32MB側で得た知見・教師や重みは、今後の小型化の研究用に残す。3MBへの構造的な圧縮と知識蒸留はまだ完了しておらず、現在のv3をその新モデルとして扱わない。

## 再現

```powershell
python scripts/build_wasm.py --runtime-model models/stories-v2-diverse-3mb --experimental-model models/everyday-v3-3mb
python scripts/serve_demo.py
```

実ブラウザーの速度測定は、Playwrightが利用できる環境で以下を実行する。

```powershell
$env:FUMIORI_BROWSER_CHANNEL='msedge'
$env:FUMIORI_TIMING_SAMPLES='30'
$env:FUMIORI_TIMING_REPORT='build/light-browser-speed.json'
node scripts/test_pages.cjs
```
